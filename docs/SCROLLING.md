# 滚动工作区（Columns 的无限画布）· 构想

> 状态：构想，v0.5 之后再评估。先把方向和开放问题记下来，避免以后推翻模型。

## 目标

把"左右并排"从"一次性把 N 个窗口切成 N 列"升级成一条**可无限延伸、首尾循环的横向窗口带**：
窗口像传送带一样排在一条长画布上，用户用滚轮/热键横向滚动，滚到尽头自动回到开头。

## 概念

| 名词 | 含义 |
|---|---|
| 画布（canvas） | 一条无限长的横向区域，所有窗口按顺序排在上面 |
| 视口（viewport） | 当前显示器可见的那一段（= 工作区） |
| 窗口带（strip） | 画布上窗口的排列序列，每个窗口有固定宽度 |
| 环绕（wrap） | 滚到末尾后继续滚动会从开头接上，形成循环 |

## 交互设想

- **滚动**：`Alt+滚轮`（横向）或专用热键（`Ctrl+Alt+←/→`）按列滚动；可配"按像素"或"按窗口"两种粒度；
- **循环**：滚到最后一个窗口之后，下一个是第一个窗口（首尾相接），永远滚不到"空白"；
- **焦点跟随**：切到窗口时自动把它滚进视口；
- **宽度**：每个窗口宽度可单独调整（复用分区模式的拖拽分隔线），默认等宽；
- **新增窗口**：追加到带尾，滚到尾部即可看到；不会挤压现有窗口宽度（与"动态分配"不同）。

## 与现有模型的关系

- 保留槽位概念：一个窗口 = 一个槽位，只是槽位沿横向排列；
- 布局引擎不再"压缩适应屏幕"，而是"排布在画布上 + 视口偏移"；
- 与分区模式共存：进入工作区时可选择"铺满"或"滚动带"（后续的布局类型之一）。

## 技术要点

- **离屏窗口**：视口外的窗口仍需真实存在（Alt+Tab、任务栏里都在）。可选做法：
  - 移到屏幕外的坐标（保留真实尺寸）——最简单，但显卡仍要合成；
  - 只在滚动时批量 `SetWindowPos`，静止时不更新；
- **环绕边界**：首尾相接时，需要把跨边界的窗口同时摆在画布两端（或用一个"影子"位置），避免滚到接缝处出现空洞；
- **滚动动画**：按帧推进 `SetWindowPos`，注意别和用户手动拖动打架；
- **DPI / 多显示器**：仍以物理像素计算，宽度按工作区比例分配；
- **性能**：窗口多时每帧移动全部窗口代价高，需要"只移动视口内 + 相邻 N 个"。

## 开放问题

1. 循环是"首尾相接"还是"到边反弹"？（首尾相接更像传送带，但接缝处理复杂）
2. 滚动粒度：按窗口（整列跳动）还是按像素（平滑）？
3. 每个窗口默认宽度：等宽 / 工作区宽度的一份 / 各自记住上次宽度？
4. 窗口数量上限：是否需要上限（比如 20 个）避免离屏窗口过多？
5. 和其它布局的关系：滚动带是"第 6 种布局"还是"左右并排的一个模式"？
6. 与 v0.4 的"替代任务栏"如何配合：工作区条是否显示整条带子的缩略图？

## 纵向变体（上下堆叠）

"上下堆叠"同样计划做成滚动带：左右两列各自纵向排列，左列略宽（默认 55%），两列可独立循环滚动（是否联动待定）。
新窗口追加到"较短"的一列（左列优先）；滚动粒度、首尾接缝的处理与横向带一致。
