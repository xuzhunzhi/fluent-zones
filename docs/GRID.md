# 智能网格（Grid）

> 目标：不是等分格子，而是"一个主窗口 + 若干小窗口环绕"的马赛克式排布，按格数自动选构图。

## 构图规则

**主窗口**（前台窗口）占左上角 62% × 62%，其余窗口按"右侧列 + 底部行"两组各自切分。

**右侧列和底部行各自切，两条分割线不必等高**——所以看起来可以是两个"日"字，左列和右列的横线错开。

### 格数与构图

| 格数 | 构图 | 1920×1080、间距 8 的实测尺寸 |
|---|---|---|
| 2 | 竖着一刀，左右 62% / 38%，两块都是全高 | `1185×1080` + `727×1080` |
| 3 | 主窗 + 右侧 1 块 + 底部 1 条横贯 | `1185×665` + `727×665` + `1920×407` |
| 4（默认） | 主窗 + 右侧 1 块 + 底部 2 块 | `1185×665` + `727×665` + `956×407` + `956×407` |
| 5 | 主窗 + 右侧 2 块 + 底部 2 块 | `1185×665` + `727×328` + `727×329` + `956×407` + `956×407` |
| 6 | 主窗 + 右侧 2 块 + 底部 3 块 | `1185×665` + `727×328` + `727×329` + `637×407` + `634×407` + `633×407` |

## 格数上限

- 设置项「最多窗口数」默认 **4**，范围 **2–6**；
- 窗口比格子多时，**多出来的窗口直接最小化**（按 Z 序、最久没用的先下去），状态栏写「最小化 N 个最久未使用的窗口」；
- 窗口比格子少时按实际数量取构图（设 6 格但只有 3 个窗口 → 用 3 格那张图），不留空格子；
- 最小尺寸装不下时：单个窗口装不下 → 弹窗问「放到主窗 / 改用层叠 / 取消」；多个都装不下 → 弹「最小化 N 个并排列 / 改用层叠 / 取消」。

## 主窗位置

当前固定左上角。右上 / 左下 / 右下属于设置项，未实现。

## 与其它组件的关系

- **一次性布局**：按上述构图直接排布，受"最多窗口数"限制；
- **分区工作区**：网格槽位就是马赛克的各个叶子，可拖拽调整主窗占比与右侧/底部边界；
- **滚动工作区（v0.5）**：网格不参与滚动，仍是一屏构图。

## 算法

```
Arrange(windows, area):
  n = min(格数上限, windows.Count)        # 超出的先最小化
  if n == 1: 铺满
  if n == 2: 竖切 ratio = 0.62
  r = (n - 1) / 2                          # 右侧列的块数（向下取整）
  b = (n - 1) - r                          # 底部行的块数，余数给底部
  top    = 横切(A, 右侧列(r 块), ratio = 0.62)
  bottom = 底部行(b 块，均分)
  root   = 竖切(top, bottom, ratio = 0.62)
```

`r` / `b` 就是下面这张表，除主窗外先对半分给右侧列和底部行，多出来的那块给底部：

| n | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|
| 右侧列 r | 0（竖切特例） | 1 | 1 | 2 | 2 |
| 底部行 b | — | 1 | 2 | 2 | 3 |

## 验收

1. 4 个窗口：主窗 62%×62%，右侧 1 块，底部 2 块，互不重叠；
2. 3 个窗口：没有底部两块，只有一条横贯全宽的底条；
3. 2 个窗口：竖着一刀，左右 62% / 38%，两块都是全高；
4. 5 / 6 个窗口：右侧列的横线和主窗下沿**不等高**；
5. 7 个窗口、格数上限 4 → 只排前 4 个，其余 3 个被最小化，状态栏说明；
6. 3 个窗口、格数上限 6 → 按 3 格排，不留空格子。
