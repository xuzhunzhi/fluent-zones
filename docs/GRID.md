# 智能网格（Grid）

> 目标：不是等分格子，而是"一个主窗口 + 若干小窗口环绕"的马赛克式排布，按窗口数量自动选最合适的构图。

## 构图规则

**主窗口**（前台窗口优先）占一块明显更大的区域，其余窗口在剩余的 L 形区域里继续分割。

### 默认 4 个窗口

```
┌───────────────┬─────────┐
│               │    B    │
│       A       ├─────────┤
│   （主窗）     │    C    │
├───────────────┴─────────┤
│            D            │
└─────────────────────────┘
```

- A：主窗，约占 62% × 62%
- B、C：右侧上下两块
- D：底部横条
- 比例都可在设置里调（主窗占比、右侧列宽、底部行高）

### 数量增多

- 5–6 个：在 B/C 或 D 里继续二分；
- 7–9 个：主窗缩到约 55%，右侧列和底部行各再分一格；
- 超过 9 个：不再细化，超出上限的窗口不参与（保持原位）。

### 数量减少

- 3 个：主窗 + 右侧上下两块（无底部行）；
- 2 个：主窗 + 右侧一块；
- 1 个：铺满工作区。

## 上限的语义

- 设置里的"最多窗口数"默认 **4**，可调到 **9**；
- **上限是意愿，不是承诺**：实际参与数 = min(上限, 按最小尺寸能装下的数量)；
- 装不下时按现有策略处理：先踢出/最小化最久未激活的，仍不行则提示；状态栏写明「上限 6，实际参与 4（最小尺寸限制）」。

## 主窗位置

默认左上角，可改为右上 / 左下 / 右下（设置项）；其余窗口围绕主窗按"先右列、再底部"的顺序填充，保持行列整齐。

## 与其它组件的关系

- **一次性布局**：按上述构图直接排布，受"最多窗口数"限制；
- **分区工作区**：网格槽位就是马赛克的各个叶子，可拖拽调整主窗占比与右侧/底部边界；
- **滚动工作区（v0.5）**：网格不参与滚动，仍是一屏构图。

## 算法草稿

```
Arrange(windows, area):
  primary = windows[0]                    # 前台优先
  rest    = windows[1..]
  if rest.Count == 0: return Fill(primary, area)

  # 依数量选构图
  if rest.Count <= 3:
      mainW = area.W * ratioW             # 默认 0.62
      mainH = area.H * ratioH             # 默认 0.62
      right  = area 右侧列（宽 area.W - mainW）
      bottom = area 底部横条（高 area.H - mainH，且只覆盖左侧宽度）
      # 右侧列上下平分 rest 里的前 2 个，剩余放底部
  else:
      # 递归：右侧列/底部行各自再二分
```

## 验收

1. 默认 4 个窗口：主窗明显更大，右侧两块上下等高，底部一条横跨左侧 + 右侧的总宽；
2. 3 个窗口：没有底部行，主窗 + 右侧两块；
3. 2 个窗口：主窗 + 右侧一块；
4. 把上限设为 6，屏幕上放不下 6 个（最小尺寸限制）→ 实际只排 4 个，状态栏说明；
5. 主窗位置改为右上时，构图左右镜像，行列仍整齐；
6. 主窗占比调整后，其余窗口按新比例重排，不重叠。
